# 02 — the codex asset pipeline (the big one)

Every pixel of art was generated by gpt-image-class models driven through
Codex CLI, supervised by Claude, art-directed by the user. The pipeline is
the real product; the images are its output.

## The operating model

Three roles, strictly separated:

- USER: art director. Rules by eye, supplies reference images, never
  writes prompts.
- CLAUDE (supervisor): writes orders, flies fleets, verifies mechanically,
  never trusts the model, reports with numbers.
- CODEX (contractor): executes one order per job. Talented, unreliable,
  forgetful. The whole pipeline exists to compensate.

"Never trust codex" is the first law. Every landing gets mechanical
verification: canvas dimensions, art bounding box, chroma coverage, hash
uniqueness across concurrent jobs, measured angles. The model claims
nothing; the ruler decides.

## Fleet mechanics

- Jobs launch detached: `nohup bash -c "codex exec ... ; echo EXIT=$? >>
  status" & disown`, one status file per job, logs per job. Sessions
  survive; a watcher polls status files and reports landings.
- Prompt goes via stdin (`codex exec ... - < order.md`); positional
  "$(cat)" args silently vanish inside nohup bash -c.
- CONCURRENCY TRAP: concurrent codex jobs sharing a working directory
  collide on image_gen temp files. Two jobs returned byte-identical PNGs
  (caught by md5). Fix: per-job `-C jobs/jN` isolation + random launch
  stagger + absolute output paths inside orders.
- image_gen sizes: 1536x1024 and 1024x1536 are exact; the "square" preset
  is 1254x1254. Ask for anything else and you get a preset anyway.

## Anatomy of an order (what years of failures taught)

An order is a markdown file with this skeleton, every section earned by a
recorded failure:

1. Attachment declarations with ROLES. "Image 1 = the COMPOSITION PLAN...
   ALL invisible constraints: obey the layout, never draw any of it."
   Models draw attached diagrams into the art unless told never to (it
   happened; the never-draw clause is blood law).
2. Canvas + chroma contract. Flat chroma green #00ff00 outside the art,
   scoped: "background key only, zero art pixels".
3. THE LAWS, ordered by priority, numbers first. Camera law, angle law,
   composition schema with pixel boxes (x=464..1072 style), width law,
   light law, style law, palette, AVOID list, verbose inventory.
4. Output contract: exact size, exact destination path, "print
   GENERATED=<path>".

Verbosity is calibrated per task: scene orders are verbose (inventory-
grade transcription of every element, or the model drifts identity); POSE
edits on isolated characters are minimal (3 sentences; verbosity degrades
pose edits — r18 lesson).

## The instrument hierarchy (the deepest lesson)

Attaching the right image beats describing, always. Ranked by measured
power:

1. CORRECTIVE ATTACHMENT: attach the model's own REJECTED render labeled
   "approved content / rejected geometry: you drew 62 degrees, the law is
   50". This is the only instrument that ever bent geometry: slab angle
   went 62 -> 55.5 -> ~50 across two corrective rounds while rules-only
   variants stayed at 62. Convergence by self-reference.
2. LAYOUT-LOCK REPAINT: attach an approved render as "THE LAYOUT IS
   CLOSED... your ONLY task is the PAINT" plus a style-gospel attachment.
   Ended the console war: all three probes held layout and flattened.
3. DRAWN LAW: a rendered diagram (angle-law green-vs-red, composition
   plans with dashed boxes and checkpoint dots, frame guides). Drawn law
   beats written law; the carpet angle war was won the round the blueprint
   became an attached image.
4. CANVAS ORIENTATION: the canvas itself composes. Landscape canvases pull
   every stall to aspect ~1.2 no matter what the text says; the portrait
   canvas (1024x1536) was the only thing that ever produced family-width
   stalls. The medium is an instrument.
5. WORLD-CAMERA GOSPEL: attach the approved neighbor stall as "copy the
   camera, zero content".
6. CHARACTER GOSPEL: attach the real reference (the Cowboy Bebop still for
   Ed) with "copy the kid, zero camera" — the still's camera looks down,
   the stall's camera is frontal, and the model can separate those if told.
7. VERBAL GEOMETRY: coordinates and angles in text. Necessary, never
   sufficient. "MEASURE the width before returning" is unexecutable by an
   image model; a proportional COVERAGE guard ("each margin ~464px, 3/4 as
   wide as the stall") at least speaks its language.

## The wars (case studies for the blog)

- THE WIDTH WAR (rounds r9-r20, never fully won on landscape): stalls
  render 15-70% wider than ordered. Frame guides, measure clauses,
  coverage guards all lost. The portrait canvas won it structurally.
  Punchline: aspect is unfixable in post (scaling preserves it), so this
  was the one war that had to be won at generation time.
- THE ANGLE WAR (console, r20): the user vectorized the platform slab as
  an SVG (trapezoid top face 130/50/50/130, rectangular 90 front face,
  sides exactly 68:81 = 50 degrees). Orders carried vertex pixels, edge
  checkpoints every 20 rows, a named callout of the previous failure's
  measured numbers, and a right-vs-wrong verdict card
  (assets/angle-verdict.png). Measured convergence: 62 -> 55.5 -> user
  acceptance. See 03 for the doctrine.
- THE ED WAR (r21): 30 strategies to get one character camera. Winners:
  silhouette-fill and place-this-exact-character. Then the user rejected
  all 30 because the real want was the full stall+Ed master — a scoping
  lesson: confirm the deliverable unit before flying 30 jobs.
- THE STALL WAR AUDIT: after 30 rejected masters the user demanded "let's
  see your instructions" and the audit convicted the supervisor: the
  shared order body carried the poison ("camera slightly LOWER", "deep
  rug", "racks ROTATED TOWARD Ed... enclosing him", multiple baselines).
  The model had obeyed. Lesson: when every job fails identically, the
  order is the bug.
- THE CONSOLE ENDGAME (r20.6-r20.11): slab doctrine -> corrective
  convergence -> layout-lock repaint (winner gen10-p2) -> too-wide
  discovery (1.81x videoclub on page) -> portrait probes -> lamp-post sign
  redesign -> final winner gen11-a by user's eye against the numbers
  (aspect 0.92, slope 61 measured; the eye ruled and the eye is the
  gate).

## Post-processing standard

Chroma key with a loose predicate (g>96, g>r+48, g>b+48), DE-GREEN cast
clamp on survivors (g capped at max(r,b)+24 — the palette has no true
greens, so this kills fringe without erosion; erosion is retired, it ate
1px rims and left halos), bbox-detect crop-back (gens ignore staging boxes
~30% of the time), border-flood + pocket key for opaque-background
returns, green-remnant conversion to translucent black for shadows.
Official keyer for magenta-era assets: codex remove_chroma_key.py, no
--despill (it executes purples).

## Verification tooling

- Per-gen: sips dims, art bbox + aspect, slab slope measured from the
  left-edge ramp (dx over dy rows), display-width projection vs the
  family ("at h=500 this displays 620 vs videoclub 342").
- Cross-stall scale: character sprite alpha-bbox heights times each
  stall's bake scale = display px. The r15 "adult=328" canvas rule never
  survived the bakes; display px is the only comparable unit. Approved
  seated Ed = 170 display px = a standing games kid.
- Galleries: every round ships an HTML gallery (gen9.html etc.) with
  cache-busted images, captions carrying the verdict numbers, and the
  reference images at top. The user judges in one tab.
